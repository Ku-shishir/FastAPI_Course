1. What does CRUD mean?

CRUD stands for:

Operation	Meaning	Typical HTTP method
Create	Add new data	POST
Read	Get data	GET
Update	Modify existing data	PUT
Delete	Remove data	DELETE

In your project:

main.py
   ↓
crud.py
   ↓
models.py
   ↓
SQLAlchemy Session
   ↓
Database

main.py receives the API request, and crud.py actually performs the database operation.

8. How main.py and crud.py work together

This is very important.

For example, your main.py has:

@app.post('/employees', response_model=schemas.EmployeeOut)
def create_employee(
    employee: schemas.EmployeeCreate,
    db: Session = Depends(get_db)
):
    return crud.create_employee(db, employee)

The responsibility is separated:

             POST /employees
                    ↓
                main.py
                    ↓
          Validate request data
                    ↓
              crud.py
                    ↓
          Perform DB operation
                    ↓
              models.py
                    ↓
                Database

This is better than putting all database queries directly inside your API endpoint.

9. Why separate crud.py?

Imagine you put everything inside main.py:

@app.post("/employees")
def create_employee(...):
    # validation
    # database query
    # insert
    # commit
    # error handling
    # response

As your application grows, main.py becomes very large.

Instead:

main.py
   → API routes

schemas.py
   → Validation

crud.py
   → Database operations

models.py
   → Database tables

database.py
   → Database connection

This makes the project more organized and easier to maintain.
